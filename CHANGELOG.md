project adheres to [Semantic Versioning](https://semver.org/) — see

## [Unreleased]

> A retrieval-quality release, plus a documentation-truth pass. It came
> out of a full review of the tree against its own docs, which turned up
> several places where `book/src/mcp-surface.md` promised behaviour the
> binary did not have. This is a **minor** bump per
> [`book/src/versioning.md`](book/src/versioning.md): the MCP wire
> surface gains tools and parameters but breaks nothing, and the on-disk
> format is unchanged (no migration).

### Fixed

- *(context)* **`mneme://context` now returns semantic memories.** The
  resource passed no query to the orchestrator and emitted a hardcoded
  `"semantic": []`, so nothing an agent ever stored with `remember`
  could reach auto-context — the resource the setup docs tell agents to
  read at session start. `book/src/mcp-surface.md` advertised
  "(optional) semantic-recall hits" and listed L4 at weight 0.7 in the
  scoring table; both were unreachable. `orchestrator::assembly`'s
  semantic scoring path was dead code in production. Seed it with
  `mneme://context?q=<text>`.
- *(context)* **The `working` (L1) section was missing from the response
  body** even though the assembler scored those turns and charged their
  tokens against the budget — so auto-context under-delivered content
  relative to the budget it reported. `docs/MEMORY_LAYERS.md` claimed the
  L1 fold-in shipped. It does now.
- *(context)* Scope was never applied: `build_context` was called with
  `None`, so `switch_scope` had no effect on the resource. Pass
  `?scope=<name>`.
- *(recall)* **Filtered recall no longer silently underfills.**
  `SemanticStore::recall` probed a fixed `limit × 4` candidates from the
  HNSW and then post-filtered by scope/kind, so asking for 10
  `work`-scoped memories out of a corpus that is a few percent `work`
  returned nearly nothing while the index held plenty. The probe now
  widens geometrically until it has `limit` survivors or the index is
  exhausted. Unfiltered recall still issues exactly one probe — the
  `recall` bench moved *down* 17 % on unchanged hardware, not up.
  Regression test pins the contract.

### Added

- *(recall)* `tags` filter (a memory must carry **every** listed tag) and
  `min_similarity`, a cosine-similarity floor so a query with no good
  match can return nothing instead of the nearest-k-however-far. Result
  rows now carry `similarity` (`1 - score`, `1.0` = identical) alongside
  the existing raw cosine `score`, which is a *distance* and was easy to
  misread as a relevance number.
- *(mcp)* **`resources/templates/list`.** Previously `method not found`,
  which left `mneme://session/{id}` undiscoverable to any spec-compliant
  client. Advertises `mneme://session/{id}` and
  `mneme://context{?q,scope,limit}`.
- *(mcp)* **Tool annotations and titles on all 13 tools.** Each
  `tools/list` entry carries `title` plus all four behaviour hints
  (`readOnlyHint`, `destructiveHint`, `idempotentHint`,
  `openWorldHint`) stated explicitly — the spec's defaults for the last
  two are wrong for this surface. A host could not previously tell
  `forget` from `stats`, so it had to prompt for everything or nothing.
- *(scopes)* **Per-project scoping.** `[scopes] derive_from_roots`
  (default `false`) derives each connection's default scope from the MCP
  client's declared workspace roots, so a host opened on
  `~/code/billing-api` writes into scope `billing-api` with no
  `switch_scope` call. Because `initialize` is per-connection this works
  in daemon mode, where one process serves many hosts. `MNEME_SCOPE`
  overrides `[scopes] default` for `mneme run` and takes precedence over
  derivation — explicit beats inferred. Off by default because enabling
  it changes where new memories land.
- *(remember)* **Near-duplicate advisory.** When new content closely
  restates an existing memory (cosine ≥ 0.95), the response carries
  `_meta.duplicate_advisory` naming the existing id and content. The
  write still lands — the verbatim principle holds — but the agent can
  choose to `update` instead of growing the corpus forever. Costs one
  index probe and **no extra embedding**: it reuses the vector already
  computed for the write.
- *(consolidation)* **Orphan-vector sweep.** Each consolidation pass now
  tombstones indexed vectors whose metadata row is gone — what a
  `forget` interrupted between its two writes leaves behind. Such
  vectors were already invisible to `recall` but still burned RAM and a
  slot in every search's candidate budget. Reported as
  `consolidation.last_orphans_reclaimed` on `mneme://stats`; a
  persistently non-zero value is worth investigating, not just
  reclaiming.

### Changed

- *(init)* `mneme init` no longer writes reserved settings that have no
  effect (`[storage] encryption`, `[mcp] sse_port`, the whole
  `[telemetry]` section) into new configs, and the starter `config.toml`
  is now commented. All three still **load** without error, so existing
  configs keep working untouched. A test fails the build if the template
  ever drifts from `Config::default()`.
- *(ci)* `benches/encryption_overhead.rs` now runs in `perf.yml`. It was
  written for v1.2 and never wired in, so the AEAD layer had no CI
  signal at all. It is gated by `check_crypto_overhead.py` as a
  *ratio* of encrypted to plain within one run, which — unlike absolute
  nanoseconds — transfers between the capture host and the runner.

### Documentation

- *(roadmap)* New [`book/src/roadmap.md`](book/src/roadmap.md): the
  single public list of what is deliberately not built yet. Previously
  every deferred item lived in a source comment, so the only way to

- *(windows)* README and the installation page now state plainly that
  **only `mneme run` works on Windows** — `mneme daemon`, `mneme client`,

  ships a Windows binary and the docs presented daemon mode as the

- *(links)* Removed public links into `proj_docs/`, which is gitignored

- *(perf)* `benches/baselines/README.md` documents the platform mismatch

  platform-matched `v1_2_2_linux_x86_64.json` reported non-blocking, and
  the promotion procedure. The blocking reference is unchanged.
- Corrected stale module docs that described shipped features as pending:
  the `tools` registry ("Phase 1 ships three stubs … that don't yet touch
  storage"), `resources` (`mneme://session/{id}` "still deferred"),
  `cli::daemon` (idle-timeout and graceful drain listed as pending; both
  landed in v1.1.1), `daemon` (serve loop "lands in a follow-up commit"),
  `index` (snapshot/load "will grow to satisfy it"), and `[daemon]` config
  ("isn't fully wired yet"). Fixed `docs/MEMORY_LAYERS.md` calling session
  snapshots `<id>.json` when the code writes `<id>.snapshot`, and
  `book/src/cli.md` omitting `opencode` from the installer's agent set.

## [1.2.2](https://github.com/tr0mb1r/mneme/compare/v1.2.1...v1.2.2) - 2026-06-07

### Security

- *(restore)* refuse archives that escape the data dir through planted
  symlinks (CWE-22). The unpack loop only validated entry *names* for
  `..`/absolute paths, so a crafted `.tar.gz` could plant a symlink
  pointing outside the data dir and then write a child file *through*
  it — an arbitrary file write as the restoring user. Each entry's
  nearest existing ancestor is now canonicalized and must stay inside
  the restore root, and any pre-existing symlink at a destination is
  unlinked before unpack. Legitimate symlink backup/restore
  round-trips are preserved; a regression test pins the contract.
- *(crypto)* wipe the `MNEME_RECOVERY_PHRASE` heap copy after KEK
  derivation (`zeroize::Zeroizing`) — the phrase is the root secret.
- *(crypto, daemon)* create the secret temp files (`keystore.json.tmp`,
  `auth.token.tmp`) at mode `0600` from the moment they exist instead
  of write-then-chmod, closing the brief umask-perms window.

## [1.0.0] — 2026-05-18

> Heading: this section marks the v1.0 cut shipped 2026-05-18. It
> promotes the cumulative stability of the v0.2.x series (MCP wire
> surface, memory layers, orchestrator, redb storage, HNSW semantic
> index, daemon-mode precursor in `mneme run`) to a 1.x API contract.
> All v0.2.6 features ship under the new version number without
> behavioral change.

### Stability promise

- **MCP wire surface** (per `book/src/mcp-surface.md`) is the
  contract that semver tracks from 1.0 onward. The Rust library API
  is private — the crate publishes a binary, not a library other
  crates depend on (per `release-plz.toml`'s `semver_check`
  configuration).
- **Schema version on disk** stays at the v0.2.x value; v1.0 is a
  surface-promise bump, not a data-format bump. Existing
  `~/.mneme/` directories from any v0.2.x release boot cleanly under
  v1.0 with zero migration work.
- **Migration test gate** (`tests/v1_0_to_v1_1_migration.rs`) pins
  the v1.0 → v1.1 forward compatibility contract; v1.0 is the first
  release this gate guards.

### Changed

- **`Forget` and `Forget::new` are now `pub(crate)`** (commit
  `1e0c8a6`). The constructor is only called from
  `src/mcp/tools/mod.rs::defaults_with_schedulers`; the previous
  `pub` visibility was an oversight that put internal tool plumbing
  into the apparent public API surface. Closes a false-positive
  semver bump that pushed release-plz PR #21 to `0.3.0`. Going
  forward every tool struct + constructor in `src/mcp/tools/` should
  follow the same pattern.
- **`release-plz.toml` sets `semver_check = false` pre-1.0** with a
  block comment recording the motivating false positive and the
  rationale: the meaningful contract pre-1.0 is the MCP wire surface
  in `book/src/mcp-surface.md`, not the Rust library API. The
  comment also flags the v1.0 cutover as the right time to
  re-enable the check, when the Rust API surface freezes alongside
  the MCP one.

### Notes

The bulk of the changelog under v0.2.0–v0.2.6 (below) is the work
that ships under v1.0 — see those sections for feature-level detail.
The v1.0 tag itself adds only the visibility fix above; the version
bump is the announcement, not new code.

## [0.2.6](https://github.com/tr0mb1r/mneme/compare/v0.2.5...v0.2.6) - 2026-05-07

Bug-fix release. Pre-1.0 PATCH (additive behaviour — no schema, API,
or config break; the `forget` tool's `inputSchema` is unchanged).

### Fixed

- **`forget(id=…)` now resolves IDs across L0 procedural and L3
  episodic, not just L4 semantic.** Previously the tool only reached
  `SemanticStore::forget`, so pin IDs and episodic event IDs both
  returned `no such memory`. That broke the agent-driven invalidation
  contract in ADR-0010 — agents had no way to clean up a polluted L3
  scope, and the only working point-delete was L4. The fix adds a
  resolution chain `L4 → L0 → L3` (first hit wins) inside the `forget`
  tool, plus a new `EpisodicStore::forget(id)` helper that walks hot
  then warm tier and reports a bool. Cold-archive entries stay out of
  reach by design — the cold quarter files are append-only and the
  180-day window is a deliberate privacy floor that pairs with the
  `record_event` opacity discipline. Verify by recording an event,
  noting its id, calling `forget(id=…)`, and confirming
  `recall_recent` no longer returns it.

### Documentation

- `book/src/mcp-surface.md` — `forget` row updated to reflect the
  cross-layer resolution and the cold-archive boundary.
- `docs/CLAUDE_CODE_SETUP.md` — clarified that `recall` accepts
  `scope` as a filter while `forget(id=…)` is scope-agnostic.
- `docs/examples/claude-code-config/CLAUDE.md` template — `forget`
  description spells out the resolution order and the cold-archive
  boundary.

## [0.2.4](https://github.com/tr0mb1r/mneme/compare/v0.2.3...v0.2.4) - 2026-05-01

Closes the L1 + L3 conversation-content gap that left those layers
tool-name-only through v0.2.3. Five architecture decisions ratified
(ADR-0007 through ADR-0011) and the v0.2.4 implementation lands the
agent-driven half. Pre-1.0 PATCH (additive only — no schema, API,
or config break; `EpisodicEvent` schema unchanged per ADR-0011).

### Added

- **`mneme.record_event` MCP tool (ADR-0008).** Unified agent-driven
  L3 producer:
  `record_event(kind, payload, tags?, scope?, retrieval_weight?)`.
  Free-form `kind: String` matches the existing `EpisodicEvent`
  schema (no enum); canonical kinds documented in the tool
  description: `user_message`, `assistant_message`, `decision`,
  `problem`, `resolution`, `milestone`, `preference`, `pivot`,
  `observation`, `summary`. Agents can invent new kinds without a
  schema migration. For `kind ∈ {user_message, assistant_message}`
  the server pushes a matching turn to `ActiveSession` (L1 mirror)
  — one tool call, both layers populated. **MCP surface 12 → 13
  tools.**
- **Enriched `tool_call` auto-emit payload (ADR-0009).** Every
  successful `tools/call` now includes the per-tool value-bearing
  arg in payload: `remember` / `pin` get `content`, `recall` gets
  `query`, `forget` / `update` get `id`, `switch_scope` gets
  `new_scope`. Diagnostic tools (`stats`, `list_scopes`, `export`)
  keep just `{tool: <name>}`. The full `arguments` object is
  **never** mirrored — explicit privacy invariant. New tools added
  to the MCP surface MUST add an extraction entry in the same PR.
  Closes the v0.2.3 gap where payloads were content-free.
- **Lifecycle auto-emits (ADR-0009).** Three new server-side events
  fire automatically with no agent action required:
  - `session_start` on `mneme run` boot — `{session_id,
    started_at, embedder, embed_dim, version, protocol}`.
  - `session_end` on graceful shutdown — `{session_id, ended_at,
    clean_shutdown, turns_total, checkpoints_total}`.
  - `tool_call_failed` on dispatch error — `{tool, error_kind,
    message}` (message capped at 500 chars). Mirrors the
    success-path emit but does NOT push a turn to L1 (failures
    don't count as turns; same logic that protected `turns_total`
    pre-v0.2.4).

### Changed

- **`Server::with_session(...)` signature** extended internally to
  take `Arc<EpisodicStore>` and `Arc<ScopeState>` so the L3
  producer + scope-aware emit have the handles they need.
  Production wiring lives in `cli::run::async_main`. Public MCP
  tool surface unchanged.
- **`docs/examples/claude-code-hooks/{stop,precompact}.sh`**
  rewritten to walk the consolidation workflow:
  `summarize_session` → `record_event(kind="summary")` →
  `remember` for durable facts → `pin` for binding rules. The
  `Stop` nudge now also recommends per-turn
  `record_event(kind="user_message"/"assistant_message")`.
- **`scripts/manual_test.sh`** strengthened from 26 → 34 checks:
  drives `record_event` end-to-end with `user_message`,
  `assistant_message`, `decision`, and an out-of-range
  `retrieval_weight`; asserts the privacy invariant on `tool_call`
  payloads (content captured, args.tags omitted); asserts
  `session_start` and `tool_call_failed` events appear in L3.

### Architecture decisions

Five ADRs ratified 2026-05-01 (`proj_docs/decisions/`):

- **ADR-0007** — L3 stays unembedded; similarity remains L4's
  exclusive job. `EpisodicStore::record_*` does not call the
  embedder; there is exactly one HNSW index in the system, owned
  by L4.
- **ADR-0008** — `record_event` tool ships in v0.2.4 (agent-driven
  conversation capture); v1.1 adds a Unix-domain-socket daemon
  control channel at `~/.mneme/control.sock` so Claude Code's
  `Stop` hook can write deterministically.

## [0.2.0] - 2026-04-29

Phase 6 (polish + release) baseline. Code-side feature work for 1.0
is complete; remaining gates are operational (30-day soak, Homebrew
formula, public release pipeline).

### Added

- **L4 semantic store** — `remember`, `recall`, `update`, `forget`
  tools backed by redb + WAL + an `instant-distance` HNSW index;
  atomic re-embedding on `update` via `WalOp::VectorReplace` +
  `HnswIndex::replace`.
- **L3 episodic store** — `recall_recent` and `summarize_session`
  tools backed by a redb hot tier and zstd-compressed cold quarters;
  consolidation scheduler promotes hot → warm → cold on idle.
- **L1 working session** — checkpoint scheduler (wall-clock + turn-
  count triggers), `mneme://session/{id}` resource, fold-in into
  `Orchestrator::build_context` so working turns participate in
  auto-context.
- **L0 procedural** — `pin` / `unpin` tools backed by a JSONL file
  with hot-reload via `notify`; `mneme://procedural` resource.
- **Auto-context** — `mneme://context` resource assembles all four
  layers under a token budget with per-layer reservations.
- **Diagnostics** — `stats`, `list_scopes`, `export` tools and
  `mneme://stats` resource with consolidation + working observability
  blocks.
- **Scoping** — `switch_scope` tool plus process-lifetime
  `ScopeState`; write tools fall back to the live scope when the
  caller omits one, filter tools treat omission as no-filter.
- **Embeddings** — BGE-M3 (default, ~1.5 GB) and MiniLM-L6 (~80 MB)
  via `candle`; automatic re-embed migration when
  `config.embeddings.model` changes; `pytorch_model.bin` weight-file
  fallback for BGE-M3; dim-mismatch tolerance during WAL replay.
- **Backup / restore** — `mneme backup` and `mneme restore`
  subcommands with full round-trip; covered by
  `cli::restore::tests::backup_then_restore_preserves_data`.
- **Schema migration** — v0 → v1 path with realistic-fixture test
  (`migrate::tests::migrates_realistic_v0_install_to_v1`).
- **CLI** — real `mneme stats` and `mneme inspect` (previously stubs
  through v0.9), `scripts/install.sh` from-source installer with
  `--minilm` and `--prefix` flags.
- **MCP** — JSON-RPC over stdio against protocol `2025-06-18`,
  12 tools, 5 resources; survives malformed JSON, oversize frames,
  and EOF cleanly.
- **Documentation** — `docs/CLAUDE_CODE_SETUP.md`,
  `docs/MEMORY_LAYERS.md`, mdBook scaffold under `book/`,
  Claude Code lifecycle hook examples under
  `docs/examples/claude-code-hooks/` with regression coverage in
  `tests/hook_scripts.rs`.
- **CI** — cross-build matrix (5 targets), `cargo-deny`,
  `cargo-audit`, GitHub Pages publication for the mdBook.
- **Release infrastructure** — `release.yml` (tag-triggered
  cross-build + GitHub Release), `release-plz.yml` +
  `release-plz.toml` (auto-bump release PRs, CHANGELOG generation).
